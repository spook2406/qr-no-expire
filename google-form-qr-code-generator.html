How a Google Form QR code works

A published Google Form has a responder link that opens the answer page. Long links look like https://docs.google.com/forms/d/e/…/viewform. The Send panel can also shorten that to https://forms.gle/…. This page checks the link, upgrades it to HTTPS, and stores that URL inside a static QR. Scanning opens the form. Whether someone can submit still depends on Google Forms: the form must be Published and accepting responses.

The code itself does not expire on our side. There is no account to lapse and no short link of ours in the image. If you later close or delete the form, scans will fail, but we do not host the form or set an expiry — reprint only when the responder link itself changes.

Copy the responder link, not the editor

In Google Forms, open Send, Share, or the Published view and copy the link respondents use. Optional Shorten URL produces a forms.gle link. That shorter string makes a less dense QR, which is easier to scan from a classroom door or a small worksheet. Do not paste the address bar while you are editing. Those URLs end in /edit or /preview, and a path that ends in formResponse is the submit endpoint, not the answer page. This generator shows an error for all three and does not build a code.

Closed forms and sign-in prompts

If the form is closed or deleted, the QR still contains the same URL, and Google — not this site — refuses the response. A sign-in prompt after scanning comes from the form’s own settings: an organization restriction, one response per person, a file-upload question, or a similar limit. That is not a broken QR. We do not help anyone bypass school or organization response or login limits.
