Two static codes, not a smart redirect

Most “app QR” tools encode one short link. The short-link server looks at the phone’s user agent and sends iPhone scanners to the App Store and Android scanners to Google Play. That short link can expire, and the code dies with the vendor. This page does not do that. It writes the official store URL into each image. A scan of the App Store code opens that App Store page. A scan of the Google Play code opens that Play page. There is no device routing and no intermediate redirect.

The codes do not expire on our side. We do not host the listing and we do not set an expiry. If an app is delisted or the store link dies, scans can fail at Apple or Google. Reprint only when the store URL itself changes. For the same idea on other payloads, see why a QR code stops working and static vs dynamic QR codes.

Which links are accepted

App Store: a public app page on apps.apple.com, with or without a country path, including /app/id plus the numeric app id. A legacy itunes.apple.com app page is rewritten to HTTPS apps.apple.com and the app id is kept. http becomes https. Tracking parameters such as utm, fbclid, and gclid are removed.

Google Play: only play.google.com/store/apps/details?id= plus the package name. http becomes https. The QR keeps the id parameter and drops referrer, utm, and every other query parameter. market://details?id= is rewritten to the matching HTTPS Play URL.

Both fields empty, the wrong store, a Play URL pasted into the App Store field (or the reverse), a search, category, developer, or marketing page, a third-party smart short link, any non-store redirect domain, and an APK or sideload download are rejected with an error. They are never silently encoded. The two payloads are never swapped.

FAQ

Is this one smart QR that opens the right store?

No. This page makes two static codes, not a device-routed smart short link. One code is the App Store URL. The other is the Google Play URL. Nothing on this site reads the user agent or redirects the scan.

Do these QR codes expire?

The codes do not expire on our side. A static QR is a picture of the store URL, so there is no trial expiry and no watermark. We do not host the apps and we do not set an expiry. No signup is required.

What if the app is delisted?

If an app is delisted or the store link dies, scans can fail. That failure is at the store, not on a timer we control. We do not host the listing and we do not set an expiry.

Is this an official Apple or Google tool?

No. This site is not official Apple or Google, and it is not affiliated with either company. You must have the right to share the store links.

Can I encode an APK or a short link?

No. We do not help with piracy or sideloading. APK and sideload links, third-party smart short links, and other redirect domains are rejected and are not encoded. Paste the public store app page.

What if I only have one store link?

Generate the one labeled static code and leave the other side empty. That is still not a device-routed smart short link. Add the second URL later and generate again if you want both codes.

Are the store links uploaded?

No. URLs are not uploaded to our server. Checking the links and drawing the QR codes run in your browser. We do not create a dynamic short link. Once this page’s assets are cached, generation still works offline.
