A booking page, not a fixed calendar event

A Calendly scheduling link opens a page where the other person picks a time. The QR stores that URL and nothing else. It does not contain a start time, an end time, or an iCalendar VEVENT. When the date and time are already chosen — a wedding, a class, a single meetup — use the Calendar Event QR generator. That tool writes a fixed ICS payload into the image. The two codes answer different questions: “book a slot on my public page” versus “add this exact event to your calendar.”

There is no device routing. A phone does not get a different destination based on its user agent. We do not mint a short link on qrstatic.app or on a third-party smart-QR service, and we do not treat those URLs as the booking link.

Which links are accepted

The host must be calendly.com. www is removed and http becomes https. The hash is dropped. Tracking parameters such as utm, fbclid, and gclid are removed. The path that identifies the booking page stays:

  • https://calendly.com/example-user — public scheduling homepage
  • https://calendly.com/example-user/30min — one event type
  • https://calendly.com/d/abc-123-xyz/intro-call — a public /d/{id} event link

Copy the link from Calendly’s share control. These examples are placeholders, not a real account.

What is rejected

Empty input is an error. So is any host other than calendly.com, including a custom domain, a short link, or an arbitrary redirect. Login, signup, app, admin, and edit pages are rejected. Cancel and reschedule links that carry an invitee token are rejected. Invite and confirmation pages are rejected. Pasting a Calendar Event, a Google Meet link, or another tool’s link is rejected. None of those are silently encoded.

The code does not expire on our side

The image is the booking URL. There is no account with us that can turn it off, and no trial clock. If you later close or delete the event type, or the Calendly account is disabled, scans fail on Calendly’s side. We do not host the booking page and we do not set an expiry. FAQ

Is this a fixed calendar event?

No. This QR is a public Calendly booking page. The other person opens it and picks a time. It is not a fixed ICS / VEVENT. For a date and time that are already chosen, use the Calendar Event QR generator.

Does this Calendly QR code expire?

The code itself does not expire on our side. A static QR is a picture of the booking URL, so there is no trial expiry and no watermark. We do not host the booking page and we do not set an expiry. No signup is required.

What if the event type is closed or the account is disabled?

If the event type is closed or deleted, or the Calendly account is disabled, scans fail on Calendly’s side. That failure is not a timer we control. We do not host the booking page and we do not set an expiry.
